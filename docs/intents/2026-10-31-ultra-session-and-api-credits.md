# Ultra 5시간 한도 없음 대응과 Claude API 키 크레딧 풀

- Status: accepted (대표 2026-10-31 그릴링 1·2라운드 답)
- 발의: 대표가 2026-10-31에 두 가지를 요청했다. ① Anthropic 요금제 변경 뒤 일부 계정에서 5시간(current session) 한도가 사라지는 것 같으니 조사하고, 화면(UI/UX)이 바뀌어야 하면 바꾼다. ② TeamClaude에 API 키 계정을 넣어, 그 키의 크레딧을 쓰고 지금처럼 크레딧 한도를 본다.
- 문제:
  1. 2026-10-30 Anthropic이 Max 20x를 Ultra로 바꾸고, 검증된 Ultra 계정부터 5시간 한도를 없앴다(공식 도움말·X 발표). 주간 한도와 Fable 주간 한도는 남는다. 라이브 풀 21개 중 1개가 5시간 값 없이 주간 값만 받는다(2026-10-31 실측). 프록시는 OAuth 계정을 5시간·주간 둘 다 있어야 "측정 완료"로 보기 때문에 이 계정을 계속 프로브하고, 메뉴바는 이 계정을 "아직 측정 안 됨"과 구분하지 못한다.
  2. 대표의 Claude 구독 계정마다 API(콘솔) 크레딧이 있다. 이것을 끝까지 쓰고 싶다. 프록시는 API 키 계정을 이미 받지만(`teamclaude api`) 크레딧 잔액을 모르고, 구독 계정과 같은 순위로 섞어 쓴다.
- 제안 결과:
  1. 5시간 한도가 없는 계정은 화면에 "5시간 한도 없음"으로 보이고, 소진 예측·계정 순서는 주간 기준으로만 계산한다. 프록시의 반복 프로브를 멈춘다. 상류 KarpelesLab/teamclaude PR #622를 참고한다(대표 답 1: 네).
  2. 이번 범위는 Claude API 키만이다. OpenAI API 키(Codex 풀)는 다음 작업이다(대표 답 2: 네).
  3. API 키 계정은 구독 계정이 모두 소진됐을 때만 쓴다(대표 답 3: 네, 2라운드 3: 구독 우선).
  4. 키를 넣을 때 충전 금액을 적고, 쓴 토큰을 모델 단가로 돈으로 바꿔 빼서 "남은 금액 약 $X"를 보여 준다. "잔액 부족" 오류가 오면 즉시 소진으로 표시하고 그 키를 뺀다(대표 답 4: 네).
  5. 지출 상한은 두지 않는다. 대표가 자동 충전을 등록하지 않아 크레딧이 0이 되면 상류가 거절하는 것으로 충분하다(대표 답 5).
  6. 관리자 키(Admin API)는 쓰지 않는다. ID 페더레이션도 쓰지 않는다(로컬 프록시에는 맞지 않음, 대표 답 6 뒤 합의).
  7. 키 등록은 터미널 명령으로만 하고, 메뉴바는 보기만 한다(대표 답 7: 네).
  8. 키는 구독 계정마다 하나씩 넣는다(2라운드 1).
- 영향: 프록시(`src/`), 상태 응답 `/teamclaude/status`, CLI `status`·TUI, 메뉴바(`menubar/`). 운영 프록시는 고정 스냅샷 패키지라 배포는 별도 결정이다.
- 제약: 런타임 의존성 0, 설정 파일 원자적 쓰기 규칙, 공개 저장소(사내 경로·계정 식별자 게시 금지), 키 값은 어디에도 출력·기록하지 않는다. 운영 프록시 재시작은 대표 결정.
- 열린 질문:
  - 구독 동봉 무료 크레딧의 만료 규칙(2라운드 2: 조사 요청). 조사 결과로 만료일 입력과 만료 임박 순서 규칙을 정한다.

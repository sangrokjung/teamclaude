# Intent: Codex 풀 주간 한도 소진 정책 (pacing vs 증설 vs 분리)

- 작성: 2026-09-22 (2026-09-23 측정 반영)
- Status: **proposed** (결정권자 판단 대기 — accepted로 바뀌면 `/intent-spec`)
- 발의: 대시보드·백엔드 검토 C1 (Codex 풀 0/7 사용 가능)

## 문제

Codex 풀(ChatGPT Pro 5계정 + 종료된 free 2계정)이 매주 화요일이면 주간 한도 100%에 닿아, 목·금까지 Codex 레인이 서지 않는다. 2026-09-23 측정에서 Pro 5계정 전부 `7d = 1.0`, 복구는 09/25 14:01 / 09/26 02:52 / 09/26 17:51 (KST) 순. 누적 입력 토큰은 계정 1~5가 3.65G · 2.79G · 2.64G · 2.39G · 1.22G로, use-or-lose 선택이 부하를 고르게 나누고 있다. 즉 **한 계정 쏠림이 아니라 총 주간 용량 부족**이다. 약 2.5일 만에 7일치를 쓰므로 현재 소비 속도는 지속 가능한 속도의 약 2.8배다.

`quotaReserve`(a9db13a)는 Claude Design 자격증명 1계정의 여유분 장치라 이 문제의 해법이 아니다. 세션 단위 소비는 프록시가 남기지 않는다(계정 단위 누적만).

## 선택지

| 선택지 | 효과 | 비용 |
|---|---|---|
| A. Pro 계정 증설 | 총 용량 증가, 코드 변경 없음 | 월 구독료 × N (2.8배 속도를 그대로 받으려면 약 +9계정) |
| B. 소비 pacing(프록시 기능) | 주간 사용률이 경과 시간 비례 pace(화요일 ≈ 2/7 ≈ 29%)를 +15%p 넘긴 계정은 선택 보류 → 매일 조금씩, 주말까지 서비스 유지 | 코드 변경(선택 로직 + status 노출 + 메뉴바 라벨) + **피크 처리량이 현재의 약 1/3로 준다** (총량은 그대로) |
| C. 세션 단위 분리 | 대량 소비 세션(무인 배치)을 워커 머신·Claude 레인으로 분리 | 운영 규칙 변경, 세션별 소비 측정이 먼저 필요(`--log-to` 1주 켜기 별도 결정) |
| D. 현행 유지 | 화~금 Codex 레인 불능 감수, `codexFallbackOnExhaustion`으로 Claude가 받음 | Claude 풀 압박 |

## 영향

- B를 고르면 프록시 계정 선택 로직·status 필드·메뉴바 라벨(소진 ↔ 보류 구분)까지 한 계획으로 묶인다.
- A·C는 코드 변경 없이 운영 결정만으로 가능하다. C는 측정 선행.

## 제약

- 총 주간 용량은 계정 수 × 플랜 한도로 고정. 어떤 pacing도 총량을 늘리지 않는다.
- 공개 저장소이므로 계정 식별자는 이 문서에 쓰지 않는다(측정 원본은 로컬 원장).

## 열린 질문

1. 화~금 Codex 불능을 감수할 것인가(D), 피크 처리량을 줄여 7일을 버틸 것인가(B), 용량을 살 것인가(A), 무인 배치를 떼어낼 것인가(C)?
2. C를 고려한다면 세션별 소비 측정(`--log-to` 1주)을 켤 것인가?
